# Storage at scale: write the change, open only what is used

Revised design against `main` at `f4e8055`. The record-command opt-in and lifetime history are settled; qualification timings remain proposals. Adopt one store per isolation boundary, one transactional record interface and two implementations: resident first, paged second. Do not partition one shared forest by a caller-supplied filter. That would couple independent writers, backups and failures. The host selects stores and authorizes handles; an ID is not a credential. No transaction spans stores.

The first qualification is **1,000,000 live nodes and 8,000,000 live links in one store**; the next is **10,000,000 nodes and 80,000,000 links**. Separately, qualify **10,000–100,000 simultaneously active stores across an installation**, plus many writers sharing one busy store (§6). These are distinct loads, not 100,000 users per store. The numeric latency and capacity targets below are proposals, not measured capabilities.

The baseline is a reference forest of 7,087 nodes of mixed kinds, in flat and structured layouts. At 1×, 10× and 100×, a tiered, sync-on-commit save took about 0.13, 1.2 and 12 seconds (medians). Fresh-process opens took about 0.3, 3.2 and 31–34 seconds. At 100× the process held 3.49–3.77 GiB, about 5.3 KiB per record; the unscoped page took 2.02–2.40 seconds. The two largest runs finished 110 and 117 of 200 saves before timeout. Four smaller reruns agreed within 3.45%. A fresh process is not a flushed filesystem cache.

## 1. Commit a command, not a forest

**Today.** In `internal/forest_lock.go`, `changeForestOp` takes a permit, stages under the forest hold, lands outside it and settles the permit. In tiered mode `stageChangeLocked` in `internal/persistence.go` calls `tier.detectChangeSet`. It walks every reachable node. The exact chain is `encodeWholeNode → json.Marshal(nodeRecord) → nodeRecord.MarshalJSON → core.EncodeRecord → orderedObject` (see `internal/change_set.go`, `internal/state_codec.go`, `core/record.go`). There is no CPU profile assigning 85% of the time to it. A flat parent's complete child list goes back into the log after every insertion. At 100×, p95 was nearly twice the median; `snapshotCold` also encodes under the same hold. The ratio is observed, not an isolated measurement of lock time.

**Built, not the final durability tier.** The old pointer path still runs this detector. In the opt-in resident profile a trusted handle supplies the issuer. One command names an occurrence, not the hash of a payload. Check its receipt under (store, issuer, command ID) before expectations; same request returns the original result, a different request conflicts. A keyed request fingerprint is a misuse check, not a deduplication index. Distinct command IDs can create identical content. Keep receipt lookup exact, including after tiering (§7).

A command compares affected data and link revisions; a link or unlink names two endpoints, never the parent's list. Validate bounded edits in order against a reversible draft; discard the whole draft on any failure. Increment touched revisions once and store sequence once per successful command. Delete detaches and tombstones; ordinary create never reuses an ID. No mutable pointer callback. Draft validation can visit an existing subtree to rule out a cycle; an insertion of a fresh leaf has no such traversal.

The tiered log carries one versioned frame per accepted command, with explicit operations, original expectations, receipt identity and resolved IDs. No per-command page root. Zero is a real append prefix, not absence. Replay requires a matching base, consecutive sequences, matching prefix/expectations and known operations. Preserve unmentioned fields and opaque slot bytes and decode numbers without binary-float coercion. Only a torn final write may be truncated; do not skip interior corruption or invent a base. The owner-writer runtime publishes after local fsync. It has no authenticated remote copy, checkpoints, sealed history, shared grants or external effect guarantee; it is explicitly selected as local-sync, not the fault-tolerant service described in §6.

|---|---|
| `b4d88f7:internal/graph` | ID grammar, expectation checks, separate revision/topology, tombstones, authorized receipt lookup; no private graph routes. |
| `9dc98f9:internal/graph` and `internal/change_set.go` | Touched-record design, with independent link/field/entry edits rather than calling `childIDs` on the parent. Explicit prefixes and raw slots in the new format. |
| `d3490bd` tiered persistence | Stage validated frames into the existing journal, recover a synced prefix and settle callers against that prefix. The old detector is confined to pointers. |
| Existing pointer and object codecs | Keep their contract. Unversioned experimental partial files are not silently imported. The pointer reader refuses even a zero-valued partial marker; use an explicit version-aware importer before any cutover. |

## 2. A caller can name a new node

**Today.** `core.NewNode` calls `GenerateNodeID` in `core/node_fn.go`; the generated IDs are not 64-character hashes. `AddChildNode` also has path/name idempotency.
**Record profile.** On the new create command, an omitted ID mints as today. A supplied ID must be exactly 64 lowercase ASCII hex digits (`semanticID` on the graph branch); reject an explicitly empty value, uppercase, truncation and aliases. Do not treat it as a content checksum. Refuse a supplied node ID that collides with a live node or reserved tombstone; ordinary creation is never an implicit overwrite or revival. A caller deriving node IDs must include an occurrence discriminator, such as a freshly minted action ID, not just the content or a coarse timestamp. A retry reuses its original IDs. Equal names are not proof of equal identities. Leave old IDs and old path creation semantics alone.
**Cost.** One resident map probe and insertion, no search through siblings or rewrite of references. Minted and supplied IDs are opaque to subsequent reads.

## 3. Links, indexes and pages

**Built:** a resident ordered index behind the record-page interface. One placement writes forward and reverse postings (all neighbors and neighbor-kind prefixes); a diamond still has one record and multiple independent edges. Removing one placement leaves the others intact. Kind and declared typed field values have their own ordered ranges, with ID as tiebreak. A write changes only affected postings and summaries; recovery derives them through the same edits. v2 returns point data or seeks one prefix/range and fetches at most one lookahead row. Summaries require an ID seek per returned row: O(log P + k log P) for k rows and P postings, not a store scan or a sort per page.

A v2 list cursor pins an in-process copy-on-write tree root and sequence, **not** a durable version root per commit. Future writes copy only changed pinned paths; without a pin updates can mutate in place. A continuation sees the old ordered summaries across commits, subject to current authority. The store owner can grant read-only access by record kind. A scoped edge page requires authority for both the anchor and the requested neighbor kind; hidden rows are never scanned to fill a page. Revocation invalidates that principal’s cursors even if the same grant is later restored. Bounded cursor eviction, fixed expiry or process restart requires restarting the query. v1 keeps its earlier restart-on-commit semantics. These are local resident indexes, not a persistent pageable backend.

**Today.** `core/node_add.go:AddChild/AddParent` already supports several distinct parents; the maps are keyed by ID. `internal/state_codec.go:linkTable` reconnects shared nodes. `internal/query_walk.go:gather/walkScope` walks the scope, prunes hidden subtrees, checks permission and deduplicates nodes. `internal/query_page.go:paginate` sorts the matches before applying a keyset cursor. `forestTx.NodeByID` also walks. The lack is an indexed read, not a second copy of a node.

**Paged design (proposed).** Store the node once. Index forward (parent, child name, child ID) and reverse (child, parent ID) links together. Check permissions at both ends for topology writes. Unlink removes one placement, not the node under its other parents. Refuse dangling links and cycles. A rename updates that node's incoming name keys. A store-local link cannot grant authority over another store; a host following an external handle opens and authorizes its destination independently.

Declare the ordered indexes at configuration time. Provide node kind and an allowlisted, typed scalar field, including a metadata key distinct from node kind. Key by equality value, requested sort value, stable tiebreak. Do not coerce missing, null, numeric and string values together. Reject incompatible index definitions or build a new generation under a pinned read root, catch up the bounded delta, then publish atomically. Charge one posting removal/insertion per changed indexed value.

| Read | Work on the indexed path (h = index height, k = returned rows) |
|---|---|
| ID at one revision | One descent, O(h), plus bytes actually returned. |
| Direct parents or children | Seek O(h), then stream O(k) consecutive postings plus authorized row fetches, up to O(k·h) cold point reads. No reverse forest walk. |
| Kind or declared-key page | Seek O(h), then k matching postings and row fetches as above. A count is two rank seeks if the index covers all filters including visibility. |
| Bounded path or descendant query | One child-name seek per path segment. Only a declared scope/depth projection qualifies for an indexed descendant page. Otherwise explicitly traverse the reachable subgraph; do not advertise an output-only bound. |

To cover the reference query, declare its metadata equality key plus descending creation time, with the existing path-based tiebreak for the compatibility response. Maintain the canonical shallowest visible path, one posting per node, and subtree counts in each qualifying posting tree. Bind a projection to its scope, depth, access class and visibility generation. A move may invalidate paths for a whole subtree; rebuild or decline the indexed plan rather than serve stale paths. Do not maintain every ancestor × reader combination. Cap declared projections per store.

Permission and expiry are checked at read time. A qualifying projection must cover the caller's exact visibility, path rules and validity interval; invalidate at the next grant expiry or relevant commit. Without such a projection, k authorized rows can require examining more than k candidates, and an exact total may require examining all of them. Keep that cost explicit; never substitute a global total. A cursor for the new paged read binds store, query, order, last key/ID, sequence and access generation with integrity protection. Reauthorize each page; on changed rights or an expired cursor lease, require a restart at an authorized version; the lease is not the lifetime of the data. Keep today's cursor/response contract on existing queries.

## 4. Sealing and owned scopes

**Today.** The pointer backend supports sealed snapshots and a separate object encryption domain. The snapshot codec has a sequence field, but the sealing path omits it. Do not put plaintext changes alongside an encrypted snapshot or reuse that envelope unchanged. Record v1 refuses incompatible configuration. Local-sync v1 does not promise confidentiality.

**Proposed.** Use a store-scoped wrapping root with versioned segment and page keys. Retain historical key generations for ordinary rotation; an authorized erasure instead supersedes a complete store generation as described in §7. Seal frames, snapshots, receipts, secondary indexes, object bodies and locators, temporary pages, replicas, archives and backups. Authenticate store, scope and generation before following a reference. Keep stores independent. Wrap all keys for a store generation, including object and backup keys, under its own generation root outside the backup set. No per-record external key or per-node key service lookup.

Authenticate store, format, purpose, epoch, segment identity, sequence/length and predecessor. Include covered sequence, root digests and journal continuation in the signed or authenticated checkpoint. Unique nonce per key/write; on reopen **or in-process retry after a failed/short write**, retire the segment and generate a new key and nonce domain before encrypting again. Never reinterpret a complete bad tag as an incomplete tail. An independent high-water mark detects rollback of a whole disk image.

Owned edits needing a witness must atomically commit it with the owner's data and receipt. Bind the writer to authenticated registration, not an input name. Legacy snapshot hooks, owned markers and grants cannot be bypassed by changing the open call; migration requires their owner's explicitly supported adapter. A local CRC, receipt MAC or file permission is not an encryption or authorization scheme.

## 5. Paged head, checkpoint and recovery

**v1 costs.** One journal since creation; open decodes and validates its history into resident maps, links, entries and receipts. Boot and RSS grow with history. Adding a sibling only records a link; even after these savings, a 100× store is GiB-scale in memory. Do not present this as paged storage. A clean populated open does not seed a user or append a transaction. Recovery may truncate a torn tail and fsync it; that is not a bootstrap mutation.

**Proposed layout.** Append immutable deltas; maintain a materialized indexed head, not a permanently retained 16 KiB tree path per command. At 18–24 copied pages/change that alternative would pin 288–384 KiB/change, up to 1.46 GiB/s at 4,000/s. Keep every command sequence in the delta history. Periodic checkpoints orient reads; old intermediate versions are reconstructed from the nearest prior checkpoint plus indexed deltas. Physical checkpoint generations are reclaimable after dependencies move, not historical roots forever.

Dirty pages and changed index runs feed a background checkpoint from a consistent sequence. Trigger by dirty bytes, tail age and measured replay time, not a 1,024-edit whole-forest barrier (at 22–44k edits/s that is tens of interruptions/s). Publish a verified generation descriptor last, with two validated recovery slots and a locator for all referenced objects. Readers pin a generation, not an unbounded pile of per-commit roots. Switch head atomically. Delete obsolete extents only after both recovery slots, readers and archive publication release them.

Size I/O and spill queues in bytes **and** count. If checkpoint/export falls behind, throttle admissions before the reserved recovery space is exhausted; never report success then drop history. No unconditional bounded recovery time under sustained overload. Replay after the chosen checkpoint must produce exactly the attested durable prefix, or hold the store unavailable pending repair. Use bounded read-ahead/buffers; do not load the complete WAL into a slice in the pageable implementation.

A broad move, descendant visibility update or grant change **must succeed without exposing partial effects**. Record a durable operation ID and preconditions, prepare a new generation in resumable bounded pages, fence/version the affected region, catch up or rebase conflicting edits, then atomically publish the roots, grant generation and final receipt. Reads stay on the prior complete state until publication. Retry resumes the operation; quota exhaustion or temporary unavailability is backpressure, not a permanent edit-count rejection. Concurrent superseding authorization still fails genuine preconditions. Test crash at every stage, old/new rights and recovery without an unbounded RAM draft.

## 6. Durability, concurrent writers and placement

**Local command path implemented.** Per-store queue; when idle commit the first ready command immediately. Drain only already waiting companions (up to 32); there is no timer. Validate a batch under the resident lock, undo tentative changes before releasing it for I/O, then publish after sync. A reader cannot observe an unconfirmed change. On failed append/sync, abandon the writer without flushing its tail, recover and sync actual bytes. Settle each admitted permit exactly once: durable if its receipt survived, refused if proven absent, unknown only if reconciliation itself fails. Fence latest reads and further admissions in the latter case. Retry with the original ID. A group is not one inseparable receipt.

**Required for machine loss; not supplied by the resident engine.** Acknowledgement in the fault-tolerant tier requires an independently durable, ordered copy of the frame, receipt and dependencies **off the writing machine**, or an equivalent synchronously durable replica. Proposed protocol: reserve a monotonic ownership epoch through a quorum service, append locally, send the ordered batch with epoch and prior commit position, and await both fsync and durable remote commit watermark. Only then publish/acknowledge and allow effects. A background upload or local epoch file does not satisfy this. If the remote barrier fails, do not acknowledge; resolve by querying the independent durable authority. Uncommitted local suffixes may not authorize receipts. A lost reply can be recovered by ID. No RPO for an unacknowledged attempt is implied; required RPO is **zero acknowledged commands** on loss of one machine.

Fence *each* remote append, checkpoint publication, archive-directory update and owner change by epoch and compare-and-set at the shared durability service. A paused or partitioned old writer cannot publish after takeover. Local file locks only exclude same-machine competitors. Handover: drain admissions, fence at sequence S, confirm the remote prefix/dependencies through S, acquire the next epoch, verify/repair the destination through S, then publish routing. On machine failure use that independent replica and quorum instead of waiting for a release certificate from the dead owner. If quorum/evidence is unavailable, stay unavailable. Measure recovery time; a stale restore must never resurrect a retired writer.

**Runtime interface.** Rust and Julia consumers only reach this engine through C. The versioned record symbols are additive (§10); migrate binding, authenticated open, expectations/receipt and retry logic before turning on commands. No assumption that either caller has migrated. A per-store receipt sequence is not the caller's per-chain sequence. A caller may compare and advance a chain counter in the same command; an effect runner must gate execution on the appropriate durable receipt, not a speculative delta. Interned u32 field IDs and typed old/new leaves remain the caller's schema responsibilities; the store preserves raw values and rejects stale bases, it does not validate a foreign schema. Keep the caller's partitioned preparation/buckets free of an installation-wide writer lock. This version still serializes final commit within one store; it is not a claim of lock-free bucket commits. Qualify or revise that boundary together before replacing an existing binding. No cross-store atomic transaction.

**Proposed scheduling model.** Replace the resident registry-wide open/close lock with a per-path promise; perform slow I/O outside the registry lock. Closed stores have no worker, FD or cache allocation. Share runners and page/FD budgets, not a goroutine and queues per closed store. Reserve hot-read capacity separately from bounded concurrent cold reads and maintenance; cold media cannot occupy every hot slot. Per-store serial queues alone cannot group fsync across 256 stores: test a separate process-level durability group mux or independent concurrent I/O and accept only actual per-store barriers. Instrument queue wait, sync concurrency and cold-device saturation.

## 7. Lifetime history and exact receipts

By default keep **every committed state in every store**; nothing is erased automatically. Only the authorized request below changes that rule. Keep history separate from its bounded crash-recovery tail. Store a compact sequence/time directory, immutable delta ranges and periodic reconstruction checkpoints. Point/range reads pin a proven sequence. History authorization uses the **current grant only**, evaluated on every read/page including archive fetch and disclosure. A newly authorized auditor may see earlier versions within today's scope; a revoked principal may not. Historical access metadata describes past facts, not present authority. Hide unauthorized keys, counts and existence. Invalidate continuations on a grant change.

An authoritative, sorted **tiered** receipt index maps store/issuer/command ID to request fingerprint and original result; an on-disk hot cache is bounded. At 2–4k commands/s, 100–150 bytes/receipt alone means roughly 16–48 GiB/day (~6–17 TiB/year) before indexes and redundancy. Do not reserve that forever on local SSD. On a local miss use exact authoritative lookup (an authenticated complete range directory or a no-false-negative filter can rule a range out; positives require exact verification). If a relevant tier cannot be read, return unavailable, not “new command.” Separate receipt uniqueness from content-addressing and from retention of payload history.

Upload immutable data, verify it at destination, then atomically publish the locator; only reclaim local bytes when checkpoints, recovery and pinned readers can resolve all dependencies. Quotas cover current head, unique historical deltas/objects, receipts, indexes, replicas, backups and migration overlap. Record physical bytes per command and archive lag. Stop admissions before exhausting recovery reserves; never delete history to clear an alarm. Cold reads verify data and charge latency for each round trip and returned byte; no substituting current data on timeout.

**Deletion on request — design, not a v2 command.** Ordinary delete remains a reversible-in-history tombstone. Only the store owner or a principal with a current, explicit erasure grant from that store’s authority may request permanent erasure of one record, a set of IDs, or the entire store. A read grant does not authorize it. Bind the authenticated requester, store, scope/IDs, request time and idempotency token to one durable intent. No TTL, idle time, account closure or storage pressure triggers erasure. No request crosses a store boundary.

1. **Fence disclosure first.** Commit the intent, reserved tombstone IDs and a disclosure-generation fence to the independent durability tier before returning “accepted”. Serialize against grants and new references. Block edits/recreation of target IDs; invalidate live and historical cursors, projections, decrypted caches, object URLs and in-flight reads at the disclosure boundary. All authorized reads, including as-of, immediately return only a tombstone (ID, requester, time, receipt), never an old payload. Unauthorized reads do not disclose existence. Whole-store requests fence every data read. Unaffected records remain readable where verified; otherwise fail closed during transition.
2. **Bounded background rewrite, not millions of keys.** Stream this store’s retained generations into a fresh independently wrapped generation, in bounded resumable chunks. Reconstruct each sequence without target payloads or derived copies; remove target log bodies, all historical page/secondary keys and values, link labels, cached projections and payload-bearing receipt fields. Rebuild indexes from sanitized source records; never copy immutable index pages unchanged. Repack surviving attachments under the new generation, including object names, keys and locators. No preserved store-wide legacy object key, target-only object or cross-store deduplication reference may unlock the old bytes. Unaffected independent records in other stores and their objects/keys are untouched.
3. **Switch and prove completion.** Replay intervening permitted writes, briefly fence publication and atomically install the verified sanitized head, history, receipt index and independent replicas. Preserve a tombstone per erased ID, even for set/whole-store requests, and the minimal control receipt; no old payload, searchable fingerprint or redirect to an old generation. Restore consults the fence before exposing any backup. Retire old roots including escrow/recovery copies, purge old objects, snapshots, cold segments, backups and caches under our control, and reconcile every inventory entry. Rewrap alone under an old retained root is insufficient. A missing/inaccessible replica, unexpired immutable plaintext backup, legal hold or unverified legacy shared attachment keeps the receipt pending, never falsely complete. An interrupted worker resumes from durable progress. Copies previously exported outside custody cannot be recalled.
4. **Cost and time.** Reduces external keys to O(active store generations), not O(records); pays O(this store’s total retained bytes + replicas/backups + affected postings/objects) in the worst case, even for one record. Temporary space is one replacement generation plus bounded buffers and the catch-up tail. For 100 GiB read + 100 GiB written at a shared effective 250 MiB/s, the streaming floor alone is ~13.7 min; add queueing, verification, replica transfer and retirement of the slowest backup. Completion is an evidenced receipt, not a promised deadline. Batch compatible requests without delaying the immediate read fences.


## 8. Qualification targets (proposals, not production measurements)

Use the 7,087/70,870/708,700-record reference graph, both layouts, fixed seed and a separate seed process. Measure the first page **before** any full traversal. Label fresh-process versus cold-device. Separate local-sync from replicated, plaintext from sealed, and single from multiple writers. For qualification repeat at least three times; report median and worst p95, sync/queue times, bytes, retries and CPU. Do not infer throughput from serial local p95.

## 9. Build and migration order

1. **Delivered:** isolated resident command format, raw deltas, receipts, local recovery, no populated-open mutation, ordered resident index/key and bidirectional pages, bounded snapshot cursors and versioned C entry points. Start new test stores only. No implicit conversion to this intermediate format.
2. **Durability before external effects:** implement independent durable replica/watermark, fenced epochs, uncertain-result recovery and machine-loss tests. Add capability negotiation; fail closed when required durability is unavailable. An embedding host must not infer replication from local success.
3. **Pageable head and importer:** define versioned primary/link/index layouts, checkpoint coverage, streaming import and scoped page correctness together. First stabilize latest pages; defer a public as-of/range API until index coverage, authorization, errors and archive semantics are defined. Keep the command/receipt wire contract.
4. **Sealing, history and receipts:** implement sealed history and recoverable key rotation before accepting confidential data; verify both checkpoints, lifetime archive, exact receipt tier, key recovery across retained generations, and isolated read budgets. Qualify large grant changes and restartable moves. Implement supported owner adapters before migrating their data.
5. **Single offline cutover to the final representation:** fence the source, use a supported source-version reader, stream validated records/edges in bounded sorted runs into a shadow final store. For old partial frames preserve exact slots, numeric lexemes and explicit prefixes; refuse missing/ambiguous bases. Stream oversized inline attachments into chunked objects; verify sizes/digests and all old-to-new locators under the same security boundary. For sealed/owned data require the matching key authority/adapter, never a plaintext detour. Size for source + final + bounded spill from measured data, not two full conversions. Checkpoint progress by source position, verify graph, revisions, receipts that actually exist and access decisions, then publish a single durable generation switch. A head-only source cannot invent earlier history; identify the history start. Retain fenced source for rollback; after new commits rollback requires lossless replay/forward repair, never switch to stale data.
6. **Rollout:** first migrate one reader/writer at a time under fenced ownership; verify projected totals/order, retry and effect gating. Then qualify multi-store placement and mixed traffic, cold reads under load and verified failover. No caller/pin changes follow automatically from this library change.

## 10. Contracts preserved; opting in

`extension/host.go` exposes freely traversable `*core.Node` pointers. Arbitrary map mutations are not cleanly interceptable. Keep the pointer engine, legacy files, base C v2 and hooks intact. Do not promise that a pageable decoder implements `ReadTx.Root()` without materializing a forest. Record handles use declarative commands and projections, **not** an automatic drop-in replacement. On the pointer path only an empty user table needs the bootstrap change; it is rechecked under the write hold. The standalone record root has no user table to seed.

See [the C record contract](record-commands.md) for the optional v1 and v2 symbols, typed index declarations, authenticated read/write opens, retry and page examples. One Go archive per process. A consumer using the base bootstrap or whole-snapshot writes must explicitly replace those writes with authorized commands, not wrap the old snapshot in one giant field. Old route sets, extension ownership, schemas and validation remain the consuming host's responsibility. A caller that still needs pointer-only behavior stays on the old profile.

## 11. Open engineering choices

1. Which independent durability service, quorum and network envelope meet the required zero acknowledged loss, and what unplanned recovery-time objective can they demonstrate?
2. Which checkpoint interval, receipt-directory layout and hot/cold budgets meet the measured replay and availability targets under sustained load?
3. For callers needing simultaneous writes to independent chains in one store, does partitioned preparation plus ordered publication suffice, or is a partitioned commit protocol required?
